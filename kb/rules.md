# CPT 判读规则知识库（rules.md）

> 来源：CPT运维SOP.docx + sql/ 目录历史诊断脚本（本地快照 2026-11-08，云端为准）
> 用途：工具生成的每条校验 SQL 必须挂接本表中的判读规则；规则必须能唯一映射到结论与动作，禁止输出"需进一步分析"这类不可执行的结论。

## R1 正常过滤类（不是问题，不标红）

| ID | 条件 | 结论 | 依据 |
|----|------|------|------|
| R1-1 | GMV大数对数 gap=100%，且该品牌在日销看板有过滤 | 正常：日销看板品牌过滤（如 HAZELINE、SKIN 下的 CLEAR 和 PONDS） | SOP 02 接口 |
| R1-2 | 机制GMV coverage < 100%，且缺失部分为机制打标/sku mapping 缺失 | 正常：接口设计上的过滤，看 coverage 即可，不按异常处理 | SOP 03 接口 |
| R1-3 | 期初理论库存 gap，且差异部分来自未打机制标的记录被过滤 | 正常：CPT 库存口径排除无机制打标记录 | SOP 05 接口 |

## R2 异常判读类（是问题，按原因归类）

| ID | 条件 | 可能原因 | 处理动作 |
|----|------|----------|----------|
| R2-1 | 机制打标表校验发现错标/漏标 | DDM 打标错误 | 输出问题清单发祝梅修复 → 修复后跑到 ADB → 重新校验，循环至通过；修复记录贴【cpt数据Check追踪】第2页 |
| R2-2 | 小样清单发现问题 | 机制表修复未覆盖 | 发 Josie & Marvin → Marvin 转祝梅修复 → 复查 |
| R2-3 | GMV大数 gap 大且非 R1-1 | 接口表 vs 校验对象表口径/数据差异 | 按校验代码逻辑逐层下钻对到细粒度；熟悉 DDM 表开发逻辑定位 |
| R2-4 | 差异源于 DDM 表逻辑问题或 DDM 数据问题 | 上游逻辑/数据错误 | 反馈业务；对接人 ddm：Teresa / cd：Lvlin |
| R2-5 | 生产脚本逻辑与需求不一致 | 逻辑变动但生产脚本未更新 | 把生产脚本拉到本地，手动改逻辑跑数 |
| R2-6 | 特殊香型机制匹配缺失 | 手工表 int_manual.ods_core_pack_variant_mapping_mf 未更新 | 按代码字段/路径要求人工上传后跑脚本 |

## R3 流程规则（什么时间做什么）

| ID | 规则 |
|----|------|
| R3-1 | Check 参数三要素：dt=数据分区（一般当天）；start_mth/end_mth=跑数月份范围；store=店铺清单 |
| R3-2 | 机制主数据必须等祝梅打完新一轮标并跑到 ADB 后才能开始校验 |
| R3-3 | 校验顺序：先主体校验（不跑拉小样代码），问题修复后再拉小样；时间紧张可同步 |
| R3-4 | 推数时机：所有 Actual 校验完毕 + 下游确认推数时间（一般晚于自动调度） |
| R3-5 | 推数时手动 trigger 所有父管道，唯一例外 PL_PAR_DIM_CORE_PACK_VARIANT_MAPPING_MANUAL |
| R3-6 | 最终产物：【1-11月 Actual Check_yyyymmdd】+【cpt数据Check追踪-yyyymm】邮件发 Robin、Josie、Winnie |
