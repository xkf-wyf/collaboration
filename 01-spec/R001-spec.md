# R001 · 需求规格：CPT 月结数据排查工具

- 版本：v0.3（待审）
- 状态：**待人类裁决**（G1 未签字，不得进入开发）
- 形态：**排查 SQL 生成器 + 判读规则**（不连库、不执行，使用者自行跑数）
- 环境：Databricks / Spark SQL / Delta
- 知识来源：`kb/`（interfaces.md / tables.md / rules.md，云端为准、本地快照 2026-11-08）
- 优先级依据：救火比造数据更急

---

## 一、v0.3 的核心变化（相对 v0.2）

1. **人类裁决**：不连 Databricks，SQL 由使用者执行（v0.2 已定，继续有效）。
2. **新增知识库依赖**：引入 `kb/` 三件套。P0 从"通用量级排查"改为 **CPT 六个接口的对数校验流程参数化**——SOP 里每个接口的 trigger 管道、Check 脚本、参数、对数 Sheet 结构、gap 处理、对接人已全部结构化入库，这是有业务含义的 P0，而不是无上下文的通用检测。
3. **知识库权威性**：云端「CPT月结」项目资料为权威源，人类审核方负责更新 `kb/`；工具与规则生成只读 `kb/`，不直接解析原始 docx/xlsx。

## 二、目标

给定一个出问题的 CPT 接口（如 GMV大数）+ 月份范围，**5 分钟内拿到该接口全部对数校验 SQL 与参数填好的对数清单模板；跑完后对照 rules.md 得出可复述的结论（含正常过滤识别）**。

| 指标 | 现状 | 目标 |
|------|------|------|
| 单接口排查耗时 | 30-120 分钟（翻 SOP + 手写 SQL + 手贴对数） | ≤ 15 分钟 |
| 手工编写 SQL 条数 | 每接口 10-20 条 | **0 条** |
| 正常过滤误报 | gap=100% 品牌需人工记忆判断 | 规则自动标注（R1-1 等） |
| 结论记录 | 散落在聊天与口头 | 强制落【cpt数据Check追踪】模板 |

## 三、用户故事

1. 我是月结运维，GMV大数管道跑完了，想让工具按 kb/interfaces.md 的 02 接口流程，生成改好参数（dt / start_mth / end_mth / store）的整套 Check SQL 和对数 Sheet 骨架。
2. 我跑完对数发现 gap=100%，想让工具直接告诉我这属于 R1-1 正常过滤（HAZELINE、SKIN 的 CLEAR 和 PONDS），不用标红，也不用找人。
3. 机制打标校验出问题，想让工具输出标准问题清单（发祝梅的格式）和【cpt数据Check追踪】记录行，含对接人速查。

## 四、功能清单

### P0（首版必须做完）

| 编号 | 能力 | 说明 |
|------|------|------|
| F1 | **六接口 Check SQL 生成器** | 按 kb/interfaces.md 参数化 01~05 接口校验逻辑 + 06 PDD 导数脚本的月份参数位。输入：接口编号、dt、start_mth、end_mth、store 清单。输出：可直接执行的 Spark SQL 集 |
| F2 | **判读规则挂接** | 每条 SQL 输出配 rules.md 中唯一规则 ID；规则必须唯一映射到"结论 + 动作 + 对接人"，禁止"需进一步分析" |
| F3 | **对数清单骨架生成** | 按各接口 Sheet 结构（如 04 接口 5 个 Sheet 的粒度定义）生成 Markdown/Excel 模板，含待填空位 |
| F4 | **问题记录模板** | 生成【cpt数据Check追踪】标准记录行与修复清单模板（对接人自动带出） |
| F5 | **量级体检 SQL（通用）** | 表级行数体检：Delta history 读 `numOutputRows` 优先，带分区过滤与 LIMIT。供接口流程之外的单表异常排查 |

## 五、非目标（本版本明确不做）

1. **不连接 Databricks，不执行任何 SQL。**
2. **不读取任何元数据。** 表结构、分区由使用者传入。
3. **不自动修复**：不生成修复脚本、不 trigger 管道、不改数据。
4. **不做调度集成、不做 Web UI、不做邮件发送。**
5. **不做全表扫描。** 所有 SQL 必须带分区过滤与 LIMIT。
6. **不猜业务主键**（若 F5 需要）。
7. **不直接解析 docx/xlsx 原始文件**，只读 `kb/`。

## 六、技术约束

- 语言：Python 3.11+
- 依赖：**仅标准库，零第三方包**（原因见取舍四）
- 知识库：只读 `kb/*.md`，其内容变更即为工具行为变更
- 输出：`.sql` 文件 + `.md` 报告/清单骨架
- SQL 方言：Spark SQL（Databricks Runtime），catalog 变量沿用 `${spark.var.catalog.*}` 写法，与现有脚本一致

## 七、关键设计取舍

1. **P0 锚定六接口而非通用检测**：SOP 里的流程与例外（gap=100% 品牌过滤、机制打标 coverage 等）是有业务含义的判读，通用工具给不出。规则来自 kb/rules.md，不凭空编。
2. **Delta 元数据优先**：`DESCRIBE HISTORY` 的 `operationMetrics.numOutputRows` 免扫表取行数，决定排查是 15 分钟还是 1 小时。
3. **一条 SQL 吐多指标**：人的成本在"切窗口-粘贴-等待"循环，合并输出减少往返。
4. **零第三方依赖**：本机 `python`(3.13) 与 `pip`(Anaconda 3.11) 错位，装包必坏。只用标准库，拷走就能跑。
5. **规则唯一映射**：每条判读必须落到"结论 + 动作 + 对接人"，写不出来的规则进"待补全"，不假装能用。
6. **SQL 自带注释头**：编号、目的、怎么读结果、对应规则 ID。
