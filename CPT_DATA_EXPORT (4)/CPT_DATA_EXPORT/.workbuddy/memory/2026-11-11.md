## 【重大】ads_bmi_golden_mf 与校验脚本 golden 侧的归店口径不一致
三方 store_name 归并逻辑对比：
- `ads_bmi_spending_mf` line 131：`case when customer='JD - REGENERATE' then 'JD - UL' else customer end` （20260904）→ **已归并**
- `ads_bmi_golden_mf` line 64：`case when store_group='JD - REGENERATE' then 'JD - UL' else store_group end`（20260904）→ **已归并**
- **校验脚本 golden 子查询（20260907 改动）把这段 case 注释掉了**，直接用 `store_group` → **未归并**

后果：CPT 的 `JD - UL` = UL + REGENERATE；脚本 golden 的 `JD - UL` 仅 UL，REGENERATE 单独成行；而 `$store` 白名单里没有 `'JD - REGENERATE'` → 该行被过滤。
⇒ `JD - UL` 上凭空出现「CPT 多算」，金额 = REGENERATE 的 RTB 花费。

**这极可能是 A 组（JD - UL / HAIR / CLEAR / CORE，33.7 万，202604 起）的主因，且性质是校验脚本 bug 而非数据问题。**
验证方式：用 `ads_bmi_golden_mf`（已归并，与 CPT 同口径）复跑 A 组，若 gap 大幅收窄即可证实。
